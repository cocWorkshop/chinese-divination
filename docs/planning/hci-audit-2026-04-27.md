# HCI Audit & Optimization Proposal — XuanJi Platform

**Date:** 2026-04-27  
**Auditor:** Claude (Senior HCI Expert)  
**Scope:** All user-facing pages, components, and interaction flows  

---

## Executive Summary

The XuanJi platform delivers a unique product — AI-powered Chinese divination — with strong visual identity (gold-on-navy, serif fonts, mystical animations). The core flow (select → fill form → wait → read result) works, but several UX friction points reduce conversion and retention. This document proposes **25 optimizations** organized by impact.

---

## 1. Navigation & Information Architecture

### 1.1 Navbar breakpoint too aggressive
**Current:** Desktop nav shows at `lg` (1024px), hamburger below.  
**Issue:** At 768–1023px (tablet portrait), users lose all nav context and must open hamburger.  
**Proposal:** Consider a compact nav variant at `md` — show icons-only for "Divination/History/Shop" with tooltips, full text at `lg`.

### 1.2 No cost transparency before entering form
**Current:** User clicks a divination type → sees form → only discovers "5 pts" cost near the submit button.  
**Proposal:** Show cost badge directly on each divination card in the selection grid (e.g. "5 pts" tag next to "Popular"). Reduces surprise and abandoned forms.

### 1.3 Missing breadcrumbs on divination flow
**Current:** User on `/divination/bazi` sees only "BaZi Analysis" heading — no "← Back to list" or breadcrumb.  
**Proposal:** Add a subtle breadcrumb or back-arrow link: `Divination > BaZi Analysis`.

## 2. Divination Form (Most Complex Page)

### 2.1 Form length overwhelms on mobile
**Current:** 8+ fields (target, calendar, date, time mode, time, gender, birthplace, environment) + privacy toggles + paipan checkbox — requires 3–4 scrolls on mobile.  
**Proposal:** 
- Group into collapsible sections: "Birth Info" (open) + "Advanced" (closed by default, contains birthplace, environment, privacy).  
- Or use a stepper: Step 1 (date/time/gender) → Step 2 (place/question) → Step 3 (review & submit).

### 2.2 Paipan-only option is buried
**Current:** "Chart only" checkbox sits below privacy toggles, above submit — easy to miss.  
**Proposal:** Move to a toggle directly below the form title: `[Full Reading] [Chart Only (free)]` as a prominent mode switch. Reduces accidental paid submissions.

### 2.3 Shichen vs Precise time UX
**Current:** Two toggle buttons ("Fuzzy" / "Precise") with a dropdown below for fuzzy and a time input for precise.  
**Proposal:** Replace toggle buttons with a single smart input:
- Default: Shichen dropdown with time ranges shown inline
- "I know my exact time" link below → switches to HH:MM input + shows true solar time info

### 2.4 Cache dialog interrupts flow
**Current:** When a matching reading exists, a modal pops up: "Found existing reading. View History / New Reading / Cancel".  
**Proposal:** Replace modal with an inline banner above the submit button: "You have a similar reading from [date]. [View it →]" — doesn't block the form.

## 3. Loading & Streaming UX

### 3.1 No progress indication during reasoning phase
**Current:** After chart_ready, LoadingOracle shows until first `value_chunk`. For Sonnet 4.6 + reasoning, this can be 2–3 minutes of animation with no progress.  
**Proposal:** Add a subtle progress bar or step indicator:
```
✓ Chart computed
⟳ AI analyzing chart... (est. 2-3 min)
○ Writing interpretation
○ Finalizing reading
```

### 3.2 Streaming blur placeholder lacks context
**Current:** Sections show gaussian blur + "此段正在由玄機大師撰寫..." placeholder.  
**Proposal:** Instead of identical text for all sections, use section-specific placeholders:
- Overview: "正在分析日主與格局..."
- Career: "正在推算事業運勢..."
- Marriage: "正在分析婚姻宮..."

### 3.3 No timeout warning
**Current:** LLM timeout is 600s. If the call hangs, the user stares at loading for 10 minutes before seeing an error.  
**Proposal:** After 3 minutes of streaming with no content, show a soft warning: "Analysis is taking longer than usual. Your reading is still being processed." After 5 minutes, offer a "Cancel and retry" button.

## 4. Reading Results

### 4.1 Chart drawer defaults open — information overload
**Current:** The chart drawer (四柱表/九宮格/飛星盤) opens by default, immediately showing dense technical data before the overview.  
**Proposal:** Default the chart drawer to **closed** for non-expert users. Add a "📊 View Full Chart" CTA that opens it. Expert users learn to click once; casual users aren't overwhelmed.  
**Alternative:** A/B test open vs closed defaults.

### 4.2 Section content has no TL;DR
**Current:** Each section (Overview, Career, Marriage, etc.) is 150–300 chars of dense prose.  
**Proposal:** Add a 1-line summary badge at the top of each section:
- Career: `📈 Overall: Favorable — key period 35-40`
- Marriage: `💛 Timing: 2028-2030 — watch for 桃花 year`
Users can scan summaries, then read the full text for details.

### 4.3 Key Predictions should highlight "now"
**Current:** Key Predictions list items with age badge, but no visual emphasis on the prediction covering the current year.  
**Proposal:** Add a highlighted border or "📍 NOW" badge to the prediction that covers the current age. Users immediately see what's relevant to them today.

### 4.4 Q&A section underused
**Current:** The XuanjiChatCard at the bottom offers 3 suggested questions + a text input. But it's at the very bottom of a long page — most users never scroll there.  
**Proposal:** Add a floating "Ask the Master" FAB (floating action button) that appears after the user has scrolled past the overview section. Clicking it scrolls to and focuses the Q&A input.

## 5. Master Chat Widget

### 5.1 Memory gate creates first-use friction
**Current:** First interaction triggers a modal requiring the user to enable/decline Master memory. The modal has ~100 words of disclosure text.  
**Proposal:** 
- Remove the blocking modal. Instead, show a one-line inline notice in the chat: "Master remembers your readings to give better advice. [Learn more]"
- Move the full disclosure to Settings → Master Memory
- This reduces the gate from 3 clicks to 0 clicks

### 5.2 Collapsed bar is easy to dismiss
**Current:** A thin bar at the bottom with emoji + truncated greeting text. Looks like a cookie banner or ad — users dismiss it mentally.  
**Proposal:** 
- Add a subtle pulse animation to the emoji on first visit (draws eye)
- After 10s on a page, show a proactive tooltip: "The Master can analyze your chart — ask anything"
- Make the greeting text 2 lines on mobile instead of truncated to 1

### 5.3 No typing indicator
**Current:** After sending a message, the user sees nothing until the first SSE chunk arrives (can be 3–5s for tool calls).  
**Proposal:** Show animated "..." dots immediately after user sends a message, before any server response.

### 5.4 CTA cards need clearer subject context
**Current:** CTA cards now show target + birth info (recently improved). But the card still feels generic.  
**Proposal:** Add the divination type icon to the card header and use a subtle background color that matches the type (gold for bazi, purple for ziwei, etc.)

## 6. Dashboard & History

### 6.1 No visual diff between reading types
**Current:** All reading cards look the same except for a small type badge. Scanning 20+ readings is hard.  
**Proposal:** Add a left-border color per type (gold = bazi, purple = ziwei, blue = iching, etc.) — similar to GitHub issue labels. Instant visual scanning.

### 6.2 Expanded reading has no "jump to" nav
**Current:** Expanding a reading shows the full result renderer — which can be 2000+ px tall. User must scroll through everything.  
**Proposal:** Add a sticky mini-nav when expanded: `[Chart] [Overview] [Career] [Marriage] [Wealth] [Health] [Q&A]` — clicking jumps to that section.

### 6.3 Delete is destructive with browser confirm
**Current:** Delete uses `window.confirm()` — plain text, no styling, no undo.  
**Proposal:** Replace with a styled inline confirmation: card turns red with "Are you sure? [Undo 5s] [Confirm Delete]". Undo auto-cancels after 5 seconds.

## 7. Subscribe / Karma Shop

### 7.1 Cost table is dense and unstructured
**Current:** Single line showing all divination costs: "BaZi 5pts · ZiWei 5pts · QiMen 5pts · MeiHua 3pts · LiuYao 3pts · IChing 3pts · FengShui 3pts · Chat Q&A 2pts · Ask Master 1pts/turn"  
**Proposal:** Group into a styled table with 2 columns:
```
Divination Types    Cost
─────────────────────────
八字/紫微/奇門       5 pts each
梅花/六爻/易經/風水   3 pts each
─────────────────────────
Chat & Master
─────────────────────────
Follow-up Q&A        2 pts
Master Chat          1 pt/turn
```

### 7.2 No "How much do I need?" guidance
**Current:** User sees 10/100/200 Karma packs but doesn't know how many readings they can do.  
**Proposal:** Add a quick calculator or example: "10 Karma = 2 BaZi readings" "100 Karma = 20 BaZi readings or 33 Liu Yao readings".

### 7.3 Discount display feels untrustworthy
**Current:** "90% OFF" badge + strikethrough price on every pack.  
**Proposal:** Either:
- Remove the permanent discount (it's clearly a marketing anchor, not a real sale)
- Or frame it as "Launch pricing — limited time" with a date

## 8. Profile & Settings

### 8.1 Tab icons are cryptic on mobile
**Current:** Profile tabs show icons only on mobile (👤, 👨‍👩‍👧, ✨, ⚙️). No text labels.  
**Proposal:** Add text below each icon on mobile: "Info · Family · Karma · Settings" — 4 words fit at 390px.

### 8.2 Family member management is clunky
**Current:** Inline editing with 8+ fields per member. Adding a new member uses the same inline form.  
**Proposal:** 
- Use a slide-out panel (drawer from right) for editing family members.
- Show only essential fields (name, relation, birth date) in the drawer; "More details" expands to time/place/gender.
- Add a quick-add button that only asks for name + relation (minimum viable).

### 8.3 Credits/transactions need visualization
**Current:** Plain ledger table with date + amount + reason.  
**Proposal:** Add a simple bar chart or timeline showing karma balance over time. Helps users understand their consumption pattern.

## 9. Accessibility (Cross-cutting)

### 9.1 Interactive elements lack semantic HTML
**Issue:** Many clickable `<div>` and `<span>` elements instead of `<button>`.  
**Impact:** Screen readers skip these; keyboard users can't reach them.  
**Proposal:** Audit and replace all `onClick` divs with proper `<button>` elements. Estimated: ~50 instances across the codebase.

### 9.2 No skip-to-content link
**Issue:** Keyboard users must tab through the entire navbar to reach main content.  
**Proposal:** Add a visually-hidden skip link as the first focusable element: `<a href="#main" class="sr-only focus:not-sr-only">Skip to content</a>`.

### 9.3 Color-only status indicators
**Issue:** Pending/failed/completed statuses use color alone (yellow/red/green).  
**Proposal:** Add text labels or icons alongside color: "⏳ Pending", "❌ Failed", "✅ Complete".

### 9.4 Chat messages not announced
**Issue:** New messages in Master Chat not announced to screen readers.  
**Proposal:** Add `aria-live="polite"` to the chat message container.

---

## 10. Performance (Cross-cutting)

### 10.1 Profile fetch on every form mount
**Issue:** `/api/init` called every time the divination form page mounts — even if profile hasn't changed.  
**Proposal:** Cache the profile response in localStorage with a 5-minute TTL. Invalidate on profile save.

### 10.2 No virtual scrolling for reading lists
**Issue:** Users with 100+ readings render all cards in DOM.  
**Proposal:** Implement virtual scrolling (e.g., `react-virtual`) for lists > 30 items.

### 10.3 StarField animation is heavy
**Issue:** Canvas-based particle animation on homepage runs continuously.  
**Proposal:** Use `requestAnimationFrame` with `prefers-reduced-motion` check. Pause when tab is not visible. Consider replacing with a static SVG gradient for mobile.
