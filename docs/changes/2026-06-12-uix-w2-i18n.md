# UIX W2 — i18n consolidation

**Date:** 2026-06-12 · **Plan:** [uix-hci-audit-2026-06-12.md](../planning/uix-hci-audit-2026-06-12.md) workstream W2

## Scope decision (deviation from the audit's original proposal)
The audit proposed a key-based dictionary (`t('error.title')`). On inspection, the codebase's inline-bilingual `T(lang, zh, en)` pattern is a defensible fit for a strictly 2-language app — both translations live at the call site and can't drift apart. The actual problems were **34 duplicated local `T` definitions**, **no Intl usage**, and **untracked coverage gaps**. W2 therefore consolidated rather than re-keyed:

## New module: `src/lib/i18n/index.ts`
- `T(lang, zhTW, en)` — THE bilingual helper; all 34 local copies deleted, every file now imports this one. `divination/[type]/constants.ts` re-exports it so its existing importers are untouched.
- `Lang` type, `toLocale()` (lang → BCP-47).
- `formatDate` / `formatDateTime` / `formatNumber` — Intl-based, locale follows the user's chosen lang.

## Gap fixes
- `profile/page.tsx` feedback dates and `delete-account/[token]/page.tsx` registration date used bare `toLocaleDateString()` (server/browser default locale) → now `formatDate(date, lang)`.
- (W0 already fixed the Chinese-only `divination/error.tsx`.)

## Guard
`scripts/check-i18n.sh` — greps for local `const T = (` re-declarations outside `src/lib/i18n` and fails with the list. Wire into CI alongside lint when convenient.

## Audit corrections
- B3's claim that email templates hardcode English dates was **wrong** — `src/lib/email.ts` expiry lines are fully bilingual. No email change needed.
- Remaining (mechanical, low priority): ~290 raw `lang === 'en'` ternaries still inline in components; they work correctly — migrate opportunistically to `T()` when touching a file. Admin pages use zh-only `toLocaleString('zh-TW')` dates — fine for an internal zh-speaking admin.
