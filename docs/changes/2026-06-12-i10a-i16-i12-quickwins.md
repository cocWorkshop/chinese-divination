# I10a + I16 + I12 — Phase 0 quick wins

**Date:** 2026-06-12 · **Plan items:** I10a, I16, I12

## I10a — Admin auth unification
`api/admin/feedback/route.ts` and `api/admin/site-feedback/route.ts` were the only 2 of ~34 admin routes doing inline `isAdmin` checks; both now use `requireAdmin()` from `src/lib/adminAuth.ts` (identical 401/403 semantics). All admin routes now share one gate — future auth-policy changes touch one file.

## I16 — a11y quick pass
- `<html lang>`: server default corrected `zh` → `zh-TW`; `LanguageContext` now syncs `document.documentElement.lang` to the user's actual choice (`en`/`zh-TW`) whenever it loads or changes. Screen readers / translation tools / SEO see the right language.
- `aria-label` (+ `aria-expanded` where applicable) added to the icon-only controls: theme toggle, language toggle, user-avatar menu, mobile hamburger (Navbar), notification bell (NotificationBell).

## I12 — Environment validation
- **New `src/lib/env.ts`** — Zod schema over all 23 env vars the codebase reads, imported as a side-effect from `src/lib/prisma.ts` (runs once per server process before any DB access).
  - **production:** missing/invalid REQUIRED var → startup ABORTS with the variable named.
  - **dev:** warning only. **build / test:** skipped (`SKIP_ENV_VALIDATION=1` already set in the Dockerfile build stage; `NODE_ENV=test`).
  - REQUIRED: `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `OPENROUTER_API_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `RESEND_API_KEY`.
- **`.env.example` rewritten** with REQUIRED/OPTIONAL tiers; previously-undocumented vars added: the **Stripe keys** (!), `OPENROUTER_MODEL`, `MASTER_MODEL`, `PORTRAIT_MODEL`, `MASTER_SESSION_STALE_HOURS`, `NEXT_PUBLIC_GA_ID`.

## ⚠ Operator instructions (I12 — behavior change)
The next production deploy will **refuse to start** if `.env.production` is missing a required var. I verified the current `.env.production` contains all 7 (and dev secrets live in `.env.local`) — **safe to deploy as-is**. If you ever rotate/remove one, the container will exit at boot with the variable named in the logs instead of failing mysteriously mid-request.
